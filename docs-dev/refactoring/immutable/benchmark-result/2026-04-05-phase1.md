## 觀察

- Phase 1 沒有帶來可觀察到的 managed allocation 改善；所有案例的配置量與 baseline 幾乎相同。
- 英文單行與英文多行轉換接近 baseline，但沒有實質加速。
- 中文單行、中文多行、長中文字串，以及中英混合多行都出現明顯退步。
- 初步推測需要用 profiler 進一步確認查表路徑的熱點，特別是 `FrozenDictionary`/`FrozenSet` 轉換後的查詢成本是否高於原先集合型別在此工作負載下的表現。

## 當時結論

以效能角度來看，Phase 1 目前應視為「功能正確，但效能退步」。若此重構的主要目標是提升轉換效能，建議先分析並處理這一批回歸，再進入 Phase 2 或更大範圍的 immutable 化工作。
