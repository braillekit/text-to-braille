# 詞庫檔案

日期：2007-09-25

**注意：** 內容可能已過時。

## 簡介

詞庫的設計，主要是為了減少使用者修正破音字的注音字根的頻率，它包含了兩個待解決的問題：

1. 在取得單一中文字的注音組字字根時，IME API 傳回的注音組字字根不完整。例如：「一」這個字，利用 ImmGetConversionList 取得注音輸入法（新注音不可用，因為只固定傳回一組）的組字字根時，只會傳回一聲的「ㄧ」。

2. 由多個中文字組成的辭彙有固定的唸法，若能處理這個部份，就能大幅減少使用者修正破音字的需要。

## 設計

### 單一中文字的注音組字字根

針對第一個問題，也就是單一中文字的注音組字字根，可以自行建立一個擴充的中文字注音字根對照檔，並且在呼叫 ImmGetConversionList 之前，先搜尋這個擴充的對照檔，如果在擴充的對照檔中有找到中文字，則取出對應的注音組字字根，並以此結果為準，也就不再呼叫 ImmGetConversionList 了。如果擴充的對照檔中找不到處理的中文字，才呼叫 ImmGetConversionList。

擴充的注音字根對照檔檔案名稱：ImmConvExt.txt。其內容格式如下：

```text
一 ㄧ ㄧˊ ㄧˋ
○ ㄌㄧㄥˊ
們 ㄇㄣ˙ ㄇㄣˊ
```

每一列代表一個中文字的所有注音組字字根，每一組字根以空白字元分隔（空白字元個數不限），第一組字根代表預設的字根。注意，像「○」這種符號，無法用注音「ㄌㄧㄥˊ」輸入，也可以利用此擴充檔實現。

### 由多個中文字組成的辭彙

**以下方法描述全部可略過，因為只要採用 Windows IME API****，並使用新注音 keyboard layout** **來取得整串中文字的注音字根，就會自動使用新注音的智慧型詞庫判斷，而且還能利用使用者造詞檔，完全不用自己寫，省卻一番功夫。不過，系統還是可以內建擴充的詞庫機制，內建幾個最常用的辭彙，以免使用者還要自行造詞（新注音造詞工具有匯入／匯出功能）。**

此問題可使用詞庫檔案來解決，其可能的使用時機有兩個：

1. 在將一篇文章的中文字逐一取得組字字根的同時，將最近取過的 N 個中文字暫存至一個緩衝區（適當的 N 值可能為 6，視詞彙的最大長度而定），並且在緩衝區滿溢時，去詞庫當中搜尋比對，已修正符合詞彙的注音字根。

2. 將一篇文章的所有中文字全都轉成注音之後，再逐字比對詞庫檔的內容以修正其注音字根。

詞庫檔可設計成兩個：

1. 系統內建詞庫（SysPhrase.txt）

2. 使用者自訂詞庫（UserPhrase.txt）

無論哪一個詞庫，原始檔都是純文字檔，以便隨時修改，但系統內建詞庫必須使用開發工具轉換成二進位資源檔，並嵌入應用程式中，一來避免被使用者修改，二來保護智慧財產。使用者在使用時如果發現有欠缺的詞彙，即可在使用者自訂詞庫中定義新詞，但要注意：如果在系統內建詞庫中已經有的詞彙，在使用者詞庫中又再定義一次，則會以使用者詞庫的定義為準（即蓋過系統內建詞庫的定義）。

### 內容格式

詞庫檔案內容的每一列代表一條詞彙，包含中文字與對應之注音組字字根。參考以下範例：

```text
一一 ㄧ ㄧ
一丁點兒  ㄧ ㄉㄧㄥ ㄉㄧㄢˇ ㄦ
```

每一條詞彙的第一欄是中文詞彙，隔一個（或多個）空白之後，就是該中文詞彙的每個中文字所對應之注音字根。

### 檔案內容的排序

系統內建詞庫的內容必須依照中文字排序，以免每次程式載入檔案時還要重新排序一次。編輯原始檔案時，可將新的詞彙直接附加在檔案後面，待完成編輯之後，利用工具將內容排序，例如：UltraEdit。你可以用 UltraEdit 開啟詞庫檔案，然後從主選單點選「File > Sort > Sort File」。系統內建詞庫編輯並排序完成後，需轉換成應用程式的資源檔，並嵌入應用程式二進位檔案中。因此，系統內建詞庫的建檔工作包含以下步驟：

1. 編輯詞庫內容。
2. 排序。
3. 轉換成應用程式資源檔。

使用者自訂詞庫則只要第 1 個步驟，當然，有排序過也是沒問題的。

### 詞庫處理流程

```text
1. 迴圈：處理一串字串
2.     N = 1
3.     迴圈：從目前的位置讀取 N 個字，比對詞庫中是否有完全符合的詞。
         - 有：取出該詞的所有注音碼；N+1；重複步驟 3。
         - 無：跳出迴圈（至步驟 7）。
       迴圈結束  
4.     判斷步驟 3 的迴圈是否取得符合的詞彙
         - 是：將該詞彙的每個字轉成點字；目前的位置 = 目前的位置+N。         - 否：
5. 重覆迴圈直到全部字串處理完畢。

注意：

- 步驟 4 在將明眼字轉成點字時，由於詞庫檔案中記錄的注音碼不像透過 IMM API 所傳回的注音碼會包含全型空白，因此，在轉點字時，判斷是否為結合韻、單音節的方法可能要改別的方法，不能再依靠全型空白來判斷。
